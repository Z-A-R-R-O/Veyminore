## 2. Runtime Alignment & Preflight Architecture

### A. Truthful Node Runtime Requirement (`>= 22.5.0`) & Genuine `DatabaseSync` Availability
- **Root Cause & Nuance**:
  1. Previously, `package.json` declared `"engines": { "node": ">=20.0.0" }`. However, `@zetro/orchestration-core/src/task-store.js` relies on built-in `node:sqlite` `DatabaseSync` for durable transactional task persistence. In Node.js, `node:sqlite` `DatabaseSync` was introduced in Node.js **v22.5.0**.
  2. **Actual Capability vs Version-Only Preflight**: Checking semver version strings alone yields `preflight: true` even if Node is launched with `--no-experimental-sqlite` (or on platforms/builds where SQLite was omitted), leading to false-positive preflight passes while SQLite runtime operations throw `ERR_UNKNOWN_BUILTIN_MODULE`. Furthermore, in Node 22.5.0–22.11.0, `node:sqlite` was experimental (requiring `--experimental-sqlite`), whereas in later releases it became unflagged.
- **Resolution**:
  - Root `package.json` and `packages/provider-config/package.json` engine metadata strictly specify `"node": ">=22.5.0"`.
  - Implemented genuine capability detection (`isDatabaseSyncAvailable`) probing `typeof DatabaseSync === 'function'` in both `scripts/zetro-check.js` and `packages/provider-config/src/doctor.js`.
  - Preflight checks fail closed with clear, actionable diagnostics distinguishing between version incompatibility (`< 22.5.0`) and disabled/unflagged SQLite capability (`--no-experimental-sqlite` or missing `--experimental-sqlite` on 22.5.0–22.11.0).

### B. Automated Workspace Package Inventory Validation
- **Root Cause**: `packages/policy` (`@zetro/policy`) was present in the codebase with a complete test suite (`packages/policy/test/*.test.js`), but was silently omitted from `SUITES` in `scripts/zetro-check.js` and missing from claimed complete inventories.
- **Resolution**:
  - Implemented dynamic manifest inventory discovery and validation (`discoverWorkspacePackages`, `validateWorkspacePackageInventory`) in `scripts/zetro-check.js`.
  - Before any suites run, the harness dynamically scans `apps/*`, `packages/*`, and `packages/antigravity-bridge/*` for `package.json` manifests, matching each against registered test suites.
  - If any workspace package is missing from `SUITES`, `zetro-check.js` fails closed with a fatal inventory mismatch error.
  - Registered `packages/policy` (`@zetro/policy`) in `SUITES` (15 total suites).

### C. Windows Portability Diagnosis & Security Accounting
1. **Directory Junction Fixtures**: On Windows NTFS, directory junctions (`fs.symlinkSync(target, link, 'junction')`) are supported without administrative privilege. In `packages/workspace-runner/test/verifier.test.js`, an explicit directory junction traversal fixture verifies that junction escapes are actively detected and rejected via `realpath` resolution.
2. **Explicit File-Symlink Skip Accounting**: For unprivileged Windows processes creating file symbolic links, `EPERM` is caught and marked skipped. **A skipped test is NOT a passed security check.** File-symlink security fixtures must be formally verified on an elevated or Developer Mode-enabled Windows release runner before release qualification.
3. **Safe Windows npm CLI Resolution**: In `packages/workspace-runner/src/verifier.js`, `resolveNpmCliPath()` locates `npm-cli.js` directly to avoid `spawn EINVAL` on Windows `.cmd` batch files (CVE-2024-27980).
4. **Harness Offline-Isolation & Sentinels**: `scripts/zetro-check.js` unconditionally deletes `ZETRO_LIVE_SMOKE` from subprocess environments, injecting loopback sentinels (`ANTIGRAVITY_LS_ADDRESS='127.0.0.1:59999'`) to guarantee zero accidental network socket connections.
