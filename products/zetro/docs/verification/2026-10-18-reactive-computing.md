# Reactive computing update — 2026-10-18

## Implemented and checked

- The universal loop consumes fresh observations, validates each canonical proposal, checks effect authority and target identity, observes after execution, and requires independent step/goal verification.
- Shared cancellation, finite port/campaign deadlines and step limits bound the run. Unknown effect outcomes halt without retry.
- Input defaults to disabled in the CLI and Windows action dispatcher. Explicit input-enabled test fixtures now declare their opt-in.
- `createReactiveComputingSkill` composes the trusted ports, owns stop/cancellation and attaches the native desktop overlay to that run.
- The product-owned Windows presentation process draws a monochrome breathing edge aura, the small reference-shaped cursor and a rounded trailing ZETRO label. It uses actual supplied physical coordinates, not a demo orbit. It is click-through and does not activate or control applications.
- Presentation is tied to session identity, admitted display bounds, finite expiry and a one-second heartbeat. Stop closes the child; a missing heartbeat clears visuals after three seconds. Reduced motion removes breathing and label lag.
- The existing browser computer preview remains explicitly labeled a visual simulation.
